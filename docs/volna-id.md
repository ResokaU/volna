# 🪪 VOLNA ID — социальный слой

VOLNA ID — это свой профиль внутри VOLNA: хэндл, имя, био, статус, аватар, друзья, подписки и личные чаты. Модуль живёт в `renderer/social.js` и спроектирован так, чтобы **хранилище можно было заменить на любое** без переписывания интерфейса.

## Как работает v1 (сегодня, без сервера)

| Слой | Технология | Что делает |
|---|---|---|
| Директория пользователей | **GitHub Gist** (токен из настроек аккаунта) | Приватный gist `VOLNA ID registry v1`, файл `volna-id-registry.json`: карточки `{handle → name, bio, status, avatar, friends, follows}` |
| Офлайн-доставка | тот же gist, файлы `inbox-<handle>.json` | Заявки в друзья и сообщения ждут пользователя, пока он офлайн; забираются и удаляются при входе |
| Рельс-тайм | **MQTT** (публичные брокеры EMQX/HiveMQ/Mosquitto — те же, что у комнат) | Мгновенная доставка сообщений/заявок, присутствие (heartbeat 25 с) |

Всё это уже есть в приложении: токен — вкладка «Ваш аккаунт» → «Облако», MQTT-библиотека — `renderer/vendor/mqtt.min.js`.

**Важно:** справочник общий на один GitHub-токен (одно «облако»). Все, кто подключил тот же токен, видят друг друга — этого достаточно для круга друзей. Для публичной соцсети нужен свой хост — см. ниже.

## Контракт адаптера хранилища

Любое хранилище — это объект из 6 методов (`SocialStore`):

```js
const MyAdapter = {
  id: 'my-host',
  available: () => true,                       // можно ли работать сейчас
  async publishProfile() {},                   // выложить свою карточку в директорию
  async fetchDirectory() { return {}; },       // { handle: {name,bio,status,avatar,friends,follows} }
  async deliver(handle, ev) {},                // доставить событие ({type:'dm'|'freq'|'facc', from, text?, ts})
  sendRealtime(topic, obj) {},                 // мгновенная доставка (можно no-op, если сервер сам разрулит)
  presenceBeat() {},                           // пульс присутствия
};
Social.use(MyAdapter);                         // ← всё, UI не меняется
```

Заготовка `RemoteAdapter` (REST + WebSocket) лежит закомментированной в `social.js`.

## Подключение своего хоста

### Вариант А — Supabase / Firebase (быстрее всего)
- `publishProfile` → upsert в таблицу `profiles`
- `fetchDirectory` → `select * from profiles`
- `deliver` → вставка в `inbox` (сервер держит очередь до прочтения)
- рельс-тайм → Realtime Channels / Firestore streams вместо MQTT

### Вариант Б — свой VPS (Node/Go, любой хостинг)
Минимальный API:

```
PUT  /profile            — карточка текущего пользователя (auth по токену)
GET  /directory          — все карточки
POST /deliver/:handle    — положить событие в очередь получателя
WS   /rt                 — двусторонний поток: клиент шлёт события, сервер пушит входящие
```

После этого `Social.use(new RemoteAdapter(url))` в `social.js` — и VOLNA ID работает на своём хосте. MQTT и Gist остаются как фолбэк в `MeshAdapter`.

## Ограничения v1 (честно)
- Справочник общий на один токен облака (для публичной соцсети — свой хост).
- Конкурентные записи в gist — last-write-wins: при одновременной записи двух пользователей в одну секунду одно событие может потеряться (для круга друзей неощутимо).
- История чатов хранится локально у обоих собеседников и синкается с профилем через облако.
